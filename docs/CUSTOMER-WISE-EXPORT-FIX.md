# Customer-wise export fix

Root cause reproduced in headless Chrome: the desktop `.rpt-toolbar-pinned` has `overflow-x:auto`; the absolutely positioned export menu is clipped by that scrolling container. A browser hit test (`elementFromPoint`) returned false for the menu item. The existing PDF/XLSX generation functions were working; no backend export endpoints exist, and no missing Axios blob configuration caused this issue.

The Customer-wise report now opts into a menu rendered through a portal outside the toolbar, anchored to the existing Export button. It shows Download PDF and Download Excel. Other reports retain the default menu behavior. Outside-click, resize and scroll dismiss the portal safely.

Exports are disabled until the loaded report matches the current customer/loan/date scope. Existing ledger rows, filters, calculations, summaries and Show Balance are reused. Filenames include customer and loan number. Download errors are cleared on retry and shown in the existing alert. Fixed widths in this report's PDF keep Opening/Current/Closing labels aligned and readable; no shared PDF builder or accounting formula was changed.

## Verification actually performed

The fixture generator creates only an in-memory SQLite database, invokes the existing customer-wise report test setup, creates multiple customers/loans and posts a collection through the real DRF API. The browser harness uses those actual report responses, checks request scopes/auth headers and never accesses production data. Company details are supplied through the existing CompanyProfileProvider with an isolated test adapter.

- Before fix: Chrome showed PDF menu item not clickable because it was clipped.
- After fix: actual Chrome mouse click triggered automatic PDF download; actual Excel menu click triggered XLSX download.
- PDF: nonempty valid header/end marker, company profile and selected customer/loan verified; opened in Chrome's PDF viewer and visually inspected. Screenshot retained.
- XLSX: reopened with XLSX parser; exact selected-loan transactions and voucher references matched the grid. Opening 0, Dr 50, Cr 20, Closing 30 Dr verified independently. Other customer's/other loan's transactions excluded.
- Custom Period + Show Balance: downloaded second workbook; date-filter request, filter heading, optional Balance column and receipt running balance checked.
- Navigate away/return: loan selection resets, reselecting the loan permits both actual downloads again.
- No browser console exceptions in the tested flow; all report request configurations carried the expected auth header. Real customer/loan/period filtering is covered by backend tests, while the browser harness supplies isolated API-response fixtures rather than a live login/server session.
- Eleven customer-wise backend tests passed on the isolated database.
- Three existing shared export validation tests passed.
- Final production build passed, with existing large-chunk warning.
- Focused read-only code review found no critical/important issues.

PDF MIME is application/pdf; XLSX is a genuine ZIP-based workbook generated by the existing XLSX writer. No server HTTP export response is involved. There are no new routes, migrations or dependencies.

Run fixture generation from backend: `.venv/Scripts/python.exe customer_export_fixture.py`. Start the frontend on port 5179 and a dedicated headless Chrome profile with debugging port 9239. No production database writes, accounting changes, deployment or push performed.
